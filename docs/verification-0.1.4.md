# Проверка Axiom Browser 0.1.4

Проверки выполнены на Windows x64. В версии прошли 33 модульных теста.

Восстановление проверено в двух режимах: с ленивой загрузкой страниц и с немедленной загрузкой всех страниц. В обоих случаях подтверждено состояние `CORE_VERIFIED`: восстановлены четыре видимые нативные вкладки, выбрана вкладка с индексом 3. Проверены реальные POST-запросы настроек, редактирования и удаления закладки, а также открытие закладки в новой вкладке. После сценария база данных успешно открылась повторно.

12-шаговая smoke-проверка завершилась состоянием `TABS_VERIFIED count=5`. Она подтвердила создание пяти вкладок, общее окружение WebView2, сохранение cookie и JavaScript-состояния, а также проверку ввода адресной строки.

В 0.1.4 исправлен случай, когда после расширения окна ранее скрытые восстановленные вкладки оставались скрытыми из-за не сброшенного `scroll_index`. В этой версии также доступны настройки запуска и восстановления, выбор Google/Bing/DuckDuckGo, домашняя страница и подтверждение закрытия нескольких вкладок; менеджер закладок с поиском, редактированием, удалением, открытием в текущей или новой вкладке и командой открытия всех закладок; защита от второго обычного экземпляра.

## Повторение сценариев восстановления

Посев и проверка выполняются отдельными запусками. Они используют профиль `.restore-profile` и не меняют основной профиль.

```powershell
cargo run --locked -- --seed-session-test
cargo run --locked -- --restore-test
```

Чтобы проверить режим немедленной загрузки всех восстановленных страниц, укажите `--restore-all` во время посева:

```powershell
cargo run --locked -- --seed-session-test --restore-all
cargo run --locked -- --restore-test
```

Smoke-проверка использует отдельный профиль `.smoke-profile`:

```powershell
cargo run --locked -- --smoke-test
```
