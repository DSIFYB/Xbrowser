# Axiom Browser — технический план v0.1

**Дата фиксации:** 13 октября 2026  
**Платформа первой версии:** Windows 10/11, x86-64  
**Цель:** быстрый, удобный браузер с низким расходом оперативной памяти, без обязательных облачных служб и собственного сервера.  
**Статус:** спецификация и план; приложение пока не реализовано.

## 1. Принятые решения

| Настройка | Значение | Поведение |
|---|---|---|
| Автоматическая экономия RAM | `true` | Фоновый менеджер вкладок включён |
| Таймаут неактивности | `300 секунд` | После 5 минут без активности вкладка становится кандидатом на сон |
| Режим | `balanced` | Сначала сон, затем условная полная выгрузка |
| Защита закреплённых вкладок | `true` | Не переводить автоматически в сон и не выгружать |
| Защита мультимедиа | `true` | Не затрагивать воспроизведение, звонки и активные медиасессии |
| Защита незавершённого ввода | `true` | Не выгружать черновики и формы; при сомнении выбирать сохранность данных |
| Ручная выгрузка | предусмотрена | Пользователь может явно выгрузить вкладку, получив предупреждение о потенциальной потере состояния |
| Работа без серверов Axiom | обязательна | Только локальная программа и прямые соединения с сайтами |

**Правило интерпретации 5 минут:** это момент *начала* экономии памяти, а не гарантированной полной выгрузки. При открытии вкладки или её активизации таймер сбрасывается. Для первой реализации предложены: сон после 5 минут; плановая полная выгрузка после 20 минут неактивности (при выполнении защитных условий); досрочная полная выгрузка после 5 минут при подтверждённой нехватке свободной RAM. Порог 20 минут — проектное предложение, а не ранее утверждённое пользовательское значение: его нужно сделать настраиваемым.

## 2. Архитектура

**Стек:**
- `Rust` — основная логика и приложение.
- `winit` — окно и основной цикл событий Windows.
- `wry` (Windows backend: `WebView2`) — встраивание веб-содержимого как дочерних представлений; один экземпляр на загруженную вкладку.
- `webview2-com` / `windows` — доступ к COM-интерфейсам WebView2, включая `ICoreWebView2_3::TrySuspend`, `Resume` и контроллер `IsVisible`.
- Нативные элементы Win32 для первого минималистичного интерфейса: панель адреса, вкладки, кнопки. Выбор конкретного UI-библиотечного слоя проверить отдельным прототипом совместимости с дочерним HWND. В дальнейшем допустим Slint, если интеграция не ухудшит стабильность и расход памяти.
- `rusqlite` — SQLite для закладок, истории, сессий и настроек.
- `serde` + `toml` — конфигурация.
- `tracing` — локальное диагностическое журналирование, без телеметрии по умолчанию.

**Важная особенность:** Rust не заменяет Chromium. Потребление сайтов, рендеринга, JavaScript и видео определяется WebView2. Нужно измерять приложение вместе с дочерними `msedgewebview2.exe`, а не только процесс оболочки.

**Среда и профили:** использовать одну общую `CoreWebView2Environment` и один User Data Folder (UDF) для обычных вкладок, чтобы разделять браузерные процессы, кэш и cookie корректным образом. Для приватного режима в будущем — отдельный временный профиль/папка данных, с корректной очисткой после закрытия. Не пытаться вручную завершать общие процессы WebView2 ради выгрузки одной вкладки.

### 2.1. Компоненты и ответственность

## 3. Жизненный цикл вкладки

```text
                    activate
     ┌───────────────────────────────┐
     │                               │
     ▼                               │
   ACTIVE -- switch away --> BACKGROUND
                                  │
                              >= 5 min
                                  │
                          guards permit?
                           │         │
                          yes       no
                           │         └──> BACKGROUND (protected)
                           ▼
                         SLEEPING
                           │   ▲
                           │   │ failed TrySuspend -> BACKGROUND
                           │
              idle >= 20 min OR RAM pressure
                           │
                    guards permit?
                           │
                          yes
                           ▼
                        DISCARDED
                           │
                       activate
                           ▼
               RECREATING -> ACTIVE
```

Различать:
- `ACTIVE`: выбранная вкладка; никогда не усыпляется или не выгружается.
- `BACKGROUND`: WebView существует, но скрыт; допускается работа мультимедиа.
- `SLEEPING`: успешная попытка `TrySuspend`, сохранена живая WebView; экономия CPU и части RAM, без гарантий полного освобождения.
- `DISCARDED`: WebView-контроллер освобождён, в памяти приложения осталась только запись вкладки (URL, заголовок, favicon, идентификатор и минимально необходимое состояние). При активизации контроллер создаётся заново и страница перезагружается.
- `RECREATING`: промежуточное состояние, чтобы избежать дублирующихся созданий и гонок.

### 3.1. Сон через WebView2

Порядок:
1. Убедиться, что вкладка неактивна, скрыта и не защищена.
2. Установить `ICoreWebView2Controller::put_IsVisible(FALSE)`.
3. Получить интерфейс `ICoreWebView2_3` и вызвать `TrySuspend` асинхронно.
4. Переходить в `SLEEPING` **только** при успешном результате callback. При `false` или ошибке оставить `BACKGROUND` и отложить повторную попытку.
5. При активации возобновить `Resume` при необходимости, показать контроллер и сбросить таймер. WebView2 также может автоматически пробуждать ставшую видимой страницу.

Нельзя считать `TrySuspend` гарантированно успешным. Нельзя применять `MemoryUsageTargetLevel.Low` одновременно с моделью `TrySuspend`/`Resume` для одной и той же вкладки: официальная документация рекомендует выбрать один подход.

### 3.2. Полная выгрузка

1. Повторно проверить все защитные флаги непосредственно перед закрытием.
2. Сохранить метаданные: полный текущий URL, заголовок, favicon, приблизительную позицию прокрутки (если доступна), время последнего посещения.
3. Сохранить состояние вкладки в SQLite и удостовериться, что операция завершена.
4. Отписаться от событий WebView2, закрыть/освободить экземпляр соответствующего контроллера и связанных ресурсов. Не завершать процессы WebView2 вручную: они могут обслуживать другие вкладки.
5. Показать в UI значок «выгружена».
6. На активации создать новую WebView в том же пользовательском профиле, перейти по URL, восстановить только допустимые метаданные.

**Ограничения:** полная выгрузка не гарантирует восстановление внутреннего состояния SPA, навигационного стека, черновиков, playback position и POST-состояния. Поэтому её нельзя применять к страницам с неизвестным/незавершённым вводом и критичными сессиями. При ручной выгрузке показывать предупреждение.

## 4. Защитные условия

**Абсолютные исключения для автоматического сна и выгрузки в v0.1:**
- текущая активная вкладка;
- закреплённая вкладка;
- воспроизведение аудио (`IsDocumentPlayingAudio`), обнаруженное активное воспроизведение видео, включая беззвучное;
- конференция/звонок/захват камеры, микрофона или экрана — по обнаруживаемым признакам; если надёжность детектирования не подтверждена, защищать домен или не выгружать;
- ввод в форме или `contenteditable` после последнего подтверждённо чистого состояния;
- активная загрузка файла, требующая этой вкладки;
- вкладка, для которой состояние данных определить не удалось, если полная выгрузка потенциально может привести к их потере.

**MediaGuard:** WebView2 предоставляет `IsDocumentPlayingAudio` и событие его изменения. Для видео без звука добавить JS-наблюдатель за `video`/`audio` (play, pause, ended). Звонки и WebRTC требуют дополнительного исследования и тестов: нельзя считать обычный детектор проигрывания исчерпывающим. Предусмотреть список сайтов «никогда не выгружать».

**FormGuard:** JS-инъекция на старте документа наблюдает события `input`/`change`, работу `contenteditable`, состояние незавершённого ввода. В Rust передавать только `dirty = true/false/unknown`, **не отправлять и не сохранять содержимое полей, пароли или текст**. Не доверять произвольным сообщениям страниц как разрешению сбросить `dirty`. Поскольку iframe, CSP, SPA и программное изменение форм могут усложнить определение состояния, сохранять `unknown` как защищённое состояние для полной выгрузки. При ошибке скрипта автоматическая полная выгрузка запрещена.

**Политика первого этапа:** безопаснее выгрузить меньше вкладок, чем потерять несохранённый пользовательский текст.

## 5. Правило экономии и состояние памяти

Сканировать вкладки каждые 30 секунд, управляя WebView2 на UI-потоке с соблюдением требований COM. Долгие операции записи и сбор статистики проводить так, чтобы не блокировать интерфейс.

**Предлагаемые дефолты:**

```toml
[memory]
auto_management = true
mode = "balanced"
suspend_after_seconds = 300
# Дополнительный дефолт v0.1 (настраиваемый):
discard_after_seconds = 1200
scan_interval_seconds = 30
min_available_ram_mb = 2048

[tab_protection]
pinned = true
active_media = true
unsaved_input = true
active_downloads = true
unknown_form_state = true

[privacy]
telemetry_enabled = false
cloud_sync_enabled = false
```

**Логика давления на память:** если свободной RAM менее 2 ГБ в течение нескольких последовательных проверок, выбирать самую старую безопасную фон-вкладку, неактивную уже 5 минут; выгружать постепенно, повторно измеряя память между операциями. Не выгружать множество вкладок одним импульсом и не пытаться «очистить всю RAM». Порог следует сделать настраиваемым и валидировать на устройствах с разным объёмом памяти.

**Псевдокод (не компилируемый Rust):**

```rust
fn memory_tick(now: Instant, tabs: &mut TabManager, pressure: MemoryPressure) {
    for tab in tabs.background_tabs_oldest_first() {
        if tab.is_active() || tab.is_protected() {
            continue;
        }
        let idle = now.duration_since(tab.last_active_at);
        if idle < Duration::from_secs(300) { continue; }

        if tab.state == TabState::Background {
            tab.request_suspend_async(); // завершение обработать callback'ом
        }

        let long_idle = idle >= Duration::from_secs(1200);
        if (long_idle || pressure.is_sustained()) && tab.can_safely_discard() {
            tab.request_discard(); // отдельно, с повторной проверкой guard-флагов
        }
    }
}
```

Важно: не проводить `discard` прямо пока `TrySuspend` ещё выполняется; переключения должны быть сериализованы или иметь версию/поколение состояния, чтобы избежать гонок с возвращением пользователя.

## 6. Интерфейс: функции первой версии

1. Одно окно, адресная строка, кнопки «назад/вперёд/обновить».
2. Вкладки: открыть, закрыть, переключить, закрепить, дублировать.
3. Индикация `active/sleeping/discarded`, ручная выгрузка.
4. Закладки и история, восстановление сессии при перезапуске; ранее открытые вкладки восстанавливать **лениво**, без одновременной загрузки всех сайтов.
5. Сочетания `Ctrl+L`, `Ctrl+T`, `Ctrl+W`, `Ctrl+Tab`, `Ctrl+Shift+T`.
6. Разрешения на микрофон/камеру/геолокацию, открытия новых окон и загрузки — с безопасными пользовательскими подтверждениями.
7. Раздел «Память»: выбранный режим, интервал, исключения, ручная выгрузка, суммарное использование памяти.
8. Локальное хранение паролей **не реализовывать самодельным шифрованием**; сначала использовать штатное управление браузерным профилем и предусмотренные механизмы Windows/движка.

Не включать в MVP облачную синхронизацию, ИИ, встроенные аккаунты, собственный движок, сотни расширений. Эти функции увеличивают сложность и иногда расход RAM.

## 8. Этапы реализации

| Этап | Реализовать | Критерий готовности |
|---|---|---|
| 0. Технический прототип | Rust, Wry, Windows, одно WebView, доступ к `controller()` и `webview()` | Сайт открывается, native-контроллер доступен |
| 1. Базовый браузер | URL, навигация, окно, 3–5 вкладок | Вкладки корректно показываются, скрываются и закрываются |
| 2. Профиль и хранилище | Общая WebView2 Environment/UDF; история, закладки, SQLite | Cookie сохраняются, сессии восстанавливаются |
| 3. Сон | 5-минутный таймер, `TrySuspend`, `Resume` | Сон происходит только для разрешённых скрытых вкладок; callback проверяется |
| 4. Защита | Pinned, audio, video, формы, allowlist доменов | Несохранённый ввод и воспроизведение переживают длительное бездействие |
| 5. Выгрузка | `DISCARDED` с освобождением WebView, восстановление URL | Память уменьшается на тестовых тяжёлых страницах; вкладки возвращаются |
| 6. Мониторинг/бенчмарки | Статистика RAM/CPU, стресс-тесты | Есть таблица замеров и устранены основные утечки |
| 7. Полировка | Горячие клавиши, загрузки, разрешения, обработка сбоев | Повседневный сценарий без критических потерь данных |

## 9. Измерения производительности

**Что мерить:**
- память основного процесса браузера;
- private bytes всех относящихся к нашему UDF процессов WebView2 (через WebView2 `GetProcessInfos`/Win32 `GetProcessMemoryInfo`), не смешивая метрики RAM и виртуальной памяти;
- системную доступную RAM; нагрузку CPU в покое и при переходах;
- запуск холодный/тёплый, задержку переключения между вкладками и реактивацию после выгрузки;
- корректность восстановления URL, cookie, позиции прокрутки;
- использование диска (UDF, кэш, профиль).

**Сценарии:** пустое окно; 1 лёгкий сайт; 5 обычных; 10 смешанных; 20 вкладок, большинство неактивны; 2 часа использования с несколькими включениями режима сна; YouTube с воспроизведением; звонок; страница с несохранённой формой; тест после аварийного завершения процесса. Сравнивать со сборкой без автоматической экономии памяти на идентичном списке сайтов и одинаковых настройках.

**Ориентиры, не обещание:** пустое окно желательно <= 300 МБ суммарно, 10 смешанных вкладок после экономии желательно 1–2 ГБ, но значения зависят от сайтов, кэша, ОС, движка и методов измерения. Порог считать исследовательской целью, не условием принятия функций. Главный KPI — измеренное снижение private bytes после выгрузки и отсутствие потери важных пользовательских данных.

## 10. Риски и ограничения

1. `TrySuspend` — best effort: не для каждой страницы и не в любой момент доступно приостановление.
2. Сон почти не равен полной выгрузке: экономия RAM может быть небольшой, пока жив WebView.
3. Полная выгрузка уничтожает состояние сайта, которое невозможно надёжно восстановить одним URL.
4. Защита незавершённого ввода на произвольных сайтах не может быть доказана на 100%; нужен консервативный режим и тестирование.
5. WebView2 зависит от установленного Microsoft Edge WebView2 Runtime, обновлений и ограничений его API.
6. Не гарантируется совместимость всех браузерных расширений Chrome или всех защитных API сайта.
7. Блокировщики рекламы могут улучшить производительность некоторых страниц, но в v0.1 их следует внедрять только после надёжной работы вкладок и безопасности.
8. Запретить произвольное управление критичными WebView/Windows API из недоверенного веб-контента. Навигационные и WebMessage-события обязательно валидировать.

## 11. Критерии готовности MVP

- [ ] Открываются современные HTTPS-сайты.
- [ ] Несколько вкладок работают в одном окне и используют совместимую общую среду WebView2.
- [ ] На фоне после 5 минут неактивности запускается **попытка** усыпления.
- [ ] Активные и закреплённые вкладки защищены.
- [ ] Музыка, видео и протестированные звонки не прерываются автоматическим менеджером.
- [ ] Страницы с незавершённым вводом не выгружаются автоматически.
- [ ] Плановая полная выгрузка безопасных вкладок проверяется после предложенного 20-минутного интервала.
- [ ] При активации выгруженная вкладка корректно пересоздаётся и перезагружается.
- [ ] История, закладки и базовые параметры переживают перезапуск.
- [ ] Суммарная RAM измеряется с учётом WebView2-процессов.
- [ ] Список исключений и режимы доступны пользователю в настройках.
- [ ] Отсутствуют обязательные облачные службы или платные серверы.
